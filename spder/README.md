# 六足机器人下位机工程说明

## 1. 工程定位

这是一个基于 **STM32F407VETx** 的六足机器人下位机工程。

当前工程的职责是：

- 通过 **USB CDC** 接收上位机发送的数据帧
- 解析出 **18 路舵机目标角度**
- 将目标角度转换为 **PWM 输出**
- 驱动六足机器人 18 路舵机动作

也就是说：

- **上位机** 负责：控制输入、步态规划、运动学解算
- **下位机** 负责：通信接收、协议解析、PWM 执行

下位机不负责逆运动学，也不直接理解“前进/后退/转向”这类高层动作语义。

---

## 2. 当前硬件与软件基础

### 主控
- STM32F407VETx

### 软件框架
- HAL
- FreeRTOS
- USB Device CDC
- Keil / MDK-ARM 工程

### PWM 输出
当前工程已配置并启动 **18 路 PWM**，用于驱动 18 个舵机：

- TIM1 CH1~CH4
- TIM2 CH1~CH4
- TIM3 CH1~CH4
- TIM4 CH1~CH4
- TIM5 CH1~CH2

所有舵机 PWM 当前统一为 **50Hz**，适用于常见 **180° PWM 位置舵机**。

---

## 3. 舵机协议约定

### 舵机类型
- 180° PWM 位置舵机

### 上位机发送内容
上位机发送：

- `int16_t angle[18]`

每路角度的含义：

- 范围：`0.0° ~ 180.0°`
- 单位：`0.1°`

例如：

- `0` -> `0.0°`
- `900` -> `90.0°`
- `1800` -> `180.0°`

### 通信帧格式
固定 42 字节：

- `Byte0`   : `0xAA`
- `Byte1`   : `0x55`
- `Byte2`   : `36`
- `Byte3`   : `SEQ`
- `Byte4~39`: 18 路 `int16_t` 小端角度数据
- `Byte40`  : 异或校验
- `Byte41`  : `0xBB`

校验规则：

- `Byte0 ~ Byte39` 逐字节异或，结果写入 `Byte40`

## 5. 主要代码结构

### `Core/Src/main.c`
主程序入口。

负责：

- HAL 初始化
- 时钟初始化
- GPIO / DMA / TIM / USART 初始化
- 启动 18 路 PWM
- 启动 FreeRTOS

### `Core/Src/tim.c`
定时器配置文件。

负责：

- TIM1~TIM5 的 PWM 参数配置
- 舵机 PWM 输出引脚复用配置

### `Core/Src/freertos.c`
FreeRTOS 初始化入口。

负责：

- 创建默认任务
- 在默认任务中初始化 USB
- 调用 `Task_Init()` 创建用户任务

### `mytask/app.c`
用户核心任务文件。

当前主要逻辑：

- `get_data()`：负责初始化接收层，读取最新协议帧
- `leg_cl()`：负责将 18 路角度转换为 PWM compare，并输出到舵机

### `USB_DEVICE/App/usbd_cdc_if.c`
USB CDC 接口层。

负责：

- 接收 USB 数据
- 将接收到的数据交给自定义传输层处理

### `lib/usb_trans.c`
USB 传输层。

负责：

- 把 USB CDC 收到的数据从回调/中断路径转交到任务上下文
- 提供统一的接收回调注册方式

### `lib/usb_receiver.c`
协议解析层。

负责：

- 解析固定 42 字节角度协议帧
- 校验帧头、长度、校验、帧尾
- 解出 18 路舵机角度
- 提供最新一帧给任务层读取

## 6. 下位机当前执行流程

整体数据流如下：

1. 上位机通过 USB CDC 发送一帧 18 路角度
2. USB CDC 接收回调收到原始数据
3. `usb_trans.c` 将数据送入接收任务
4. `usb_receiver.c` 按协议解析出 18 路角度
5. `get_data()` 拿到最新目标角度
6. `leg_cl()` 周期执行：
   - 限幅到 `0 ~ 1800`
   - 做方向修正
   - 做零位偏移修正
   - 转换成 PWM compare
   - 刷新 18 路舵机输出

## 7. 当前版本的设计特点

### 已实现
- 18 路 PWM 启动
- 18 路舵机角度协议解析
- 基本角度限幅
- 每路舵机方向修正接口
- 每路舵机偏移修正接口

### 当前默认值
- 所有舵机默认方向：`+1`
- 所有舵机默认偏移：`0`
- 默认中位角度：`90.0°`

也就是说，当前工程已经具备“上位机发角度、下位机执行”的第一版基础能力。

## 8. 后续建议

后续联调时，建议按以下顺序进行：

1. 先发送全 18 路 `900`
   - 验证所有舵机是否都到中位
2. 再单独测试每一路
   - 验证通道顺序是否正确
3. 校准每路方向 `direction`
4. 校准每路零位偏移 `offset_ddeg`
5. 最后再接入完整上位机步态与动作控制

## 9. 注意事项

### 1）舵机方向
左右腿、镜像腿的机械安装方向可能不同。

如果某一路运动方向反了，不需要改协议，只需要修改该舵机的方向参数。

### 2）舵机中位
如果某一路舵机在 `90°` 时机械姿态不正，需要修改该路的偏移参数。

### 3）协议调试
第一版建议始终先用固定角度测试，不要一开始就发送连续运动轨迹。

### 4）通信异常
当前第一版策略是：

- 如果暂时收不到新帧，保持最后一次有效角度

后续如果需要更安全的行为，可以再加入回中或保护动作。

---

## 10. 一句话总结

这是一个 **“上位机解算、下位机执行”** 的六足机器人舵机控制工程。

它的核心目标不是在 STM32 上做复杂控制，而是：

> **稳定地接收上位机发来的 18 路角度，并准确地输出到 18 路舵机。**
